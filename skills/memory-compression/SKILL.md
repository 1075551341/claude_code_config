# 上下文与交接

在有意义的任务断点保存必要状态，不依赖固定模型窗口大小。
宿主有可靠上下文用量时，接近预算前完成当前原子步骤并交接；没有指标时按任务规模和剩余工作判断。

保留目标、验收、已确认决策及理由、当前改动、验证命令和结果、未完成项、下一步、约束与踩坑。
压缩重复日志和可重建搜索过程；保留失败证据及未知项，不把推测写成事实。

优先使用项目已有文档：长期决策放 ADR，计划与状态放现有规格目录，行为变化放变更记录。
没有既有结构且确有跨会话需要时用轻量 `spec/<project>/`，小任务不创建整套制品。

记忆能力可用时检索已确认偏好；写入前确认适用范围与授权，不存秘密。
记忆插件不是唯一事实源，也不替代当前文件和运行状态。系统原生压缩命令由宿主处理，不用同名自定义命令覆盖。

交接按“目标—已完成及证据—关键决策—当前改动—未完成与下一步—约束”组织。
