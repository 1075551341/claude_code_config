# 上下文与交接

在有意义的任务断点保存必要状态，不依赖固定模型窗口大小。宿主有可靠上下文用量时，接近预算前完成当前原子步骤并交接；没有指标时按任务规模和剩余工作判断。

## 保留与丢弃

- **保留**：目标与验收、已完成项及 `[已实测验证]` 命令/输出、关键决策及理由、当前改动文件、**已排除方案与失败尝试（附一句理由，避免下轮重踩）**、未完成项与下一步、约束与踩坑。
- **丢弃**：可重建的搜索过程、重复日志与寒暄；不把推测或未实测项写成已确认事实。

## 落盘与模板

- 优先使用项目已有文档：长期决策放 ADR，计划与状态放现有规格目录，行为变化放变更记录。
- 没有既有结构且确有跨会话需要时，使用轻量 `spec/<project>/` 或 `templates/artifacts/STATE.md`；单次交接亦可按需参照 `catalog/skills/handoff/SKILL.md`；小任务不创建整套制品。
- 记忆能力可用时先查索引/已确认偏好再按需读取详情；写入前确认范围与授权，不存秘密。记忆插件不是唯一事实源，也不替代当前文件与运行状态；系统原生压缩命令由宿主处理，不用同名自定义命令覆盖。

交接结构：**目标与验收 — 已完成与验证证据 — 关键决策及理由 — 当前改动 — 已排除方案与失败尝试 — 未完成项与下一步 — 约束与未知项**。
