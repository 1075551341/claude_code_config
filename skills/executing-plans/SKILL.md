# 计划执行

## 流程
1. 读取 writing-plans 生成的计划文档
2. 按依赖顺序执行每个任务
3. 每个任务完成后独立验证
4. 任务失败时隔离问题，不污染其他任务
5. 全部完成后：有代码/配置改动先走双审（修改者与审查者分角色），再交叉验证 + 短 R20

## 双审（修改→验证→审查；角色分离）

一轮 = **修改** → **验证**（对照原始要求，贴观察输出）→ **独立审查全部修改**。

**角色（禁止混用）**：
- **修改** → `Task` `change-implementer`（fresh）。Cursor 无该 `subagent_type` 时用 `generalPurpose`，prompt 必须声明「你是修改者，禁止审查」。禁止审查者改文件。
- **审查** → `Task` `eng-reviewer`（**每轮全新开审**，禁止 `resume` 上一轮审查者）。只对照原始要求找问题（是否符合预期），禁止改文件、禁止提交补丁。上轮清单仅作参考，不得限定本轮扫描范围。
- **主会话**：编排 + 跑验证命令 + R20；不在审查回合自己改代码。

**提前结束**：独立审查干净 `PASS`（无必须修项）且与验证结论一致 → **立即结束**，禁止第 2、3 轮。
**再开一轮（集中改）**：审查给出**完整未满足清单**后，主会话再派**一次** `change-implementer` 按清单一次改齐。禁止发现一条就立刻改、禁止边审边改耗轮次。改完再验证后，**全新派**下一轮 `eng-reviewer`（禁止 `resume`）。最多 3 轮。禁止只连审不改、禁止只汇报等用户。

有代码/配置改动即走本循环（不只非简单）。纯只读问答/调研、仅计划文件、计划未批准 → 不走。

1. `change-implementer` 按批准设计改完（含文档/注释同步）；主会话贴观察证据
2. `eng-reviewer` 对照原始要求审完全部 diff + IMPACT/blast（一次找齐，禁止发现第一条就停审），结论 `PASS` 或 `NEEDS-CHANGES`（完整未满足清单）
3. 干净 `PASS` / 符合预期 → 主会话输出短 R20 后即可完成；**禁止再派审查**
4. `NEEDS-CHANGES` → 主会话汇总清单后派一次 `change-implementer` **集中改齐**；主会话再验证（同方案 ≤R5），再开一轮**全新**独立审查（禁止 `resume` 上一轮审查者；对照原始要求全量重扫，上轮清单不得限定范围）（计数 +1）
5. 满 3 轮仍不符合预期 → `BLOCKED` / `DONE_WITH_CONCERNS`，禁止第 4 轮、禁止空转
6. 计划未批准 / CreatePlan 等待用户 → 禁止启动审查或声称完成

## 原则
- 遵循 R10 简洁优先 + R11 安全默认
- 每个子任务有明确成功标准
- 无依赖的子任务可并行
- 执行过程中发现计划缺陷，返回 plan 阶段修正

## 进度追踪（task-master 风格）

- Checkbox 可视化：`- [ ] 待办` / `- [x] 完成`
- 阶段进度：`Phase 1/3 — ██████░░░░ 60%`
- 依赖状态标记：`→ T2（pending）` / `✓ T2（completed）`
- 每完成一个任务输出进度更新
