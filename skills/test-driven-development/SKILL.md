# TDD（显式启用）

1. RED：为一个预期行为写失败测试，运行并确认失败来自预期原因。
2. GREEN：写使该行为通过的最小实现，不提前扩展其他行为。
3. REFACTOR：在测试保护下改进结构，每步仍通过。

测试关注行为及正常、边界、错误和回归场景；避免顺序依赖、真实网络与不可控时间。
不得通过删除测试、放宽断言或大量 mock 掩盖集成被破坏。用户明确需要特征测试时，先记录既有行为再修改。

记录实际红、绿和重构输出；TDD 不替代任务风险所要求的验证与独立审查。
