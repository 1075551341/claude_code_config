# TDD（显式启用）

1. RED：为一个预期行为写失败测试，运行并确认失败来自预期原因（而不是语法或环境错误）。
2. GREEN：写使该行为通过的最小实现，不提前扩展未测试行为，不添加无关兜底分支。
3. REFACTOR：在测试保护下改进结构（共性逻辑适时收拢公共层），每步保持通过。

测试关注外部可观察行为及正常、边界、错误（预期失败）和回归场景；避免顺序依赖、真实网络与不可控时间。
不得通过删除测试、放宽断言、复刻实现逻辑或大量 mock 掩盖集成被破坏。用户明确需要特征测试时，先记录既有行为再修改。

记录实际红、绿和重构输出并标注 `[已实测验证]`；TDD 不替代任务风险所要求的验证与独立审查。
