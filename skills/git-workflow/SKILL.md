# Git 与交付准备

尊重仓库已有分支与提交约定；不为小项目强加多层分支模型。先检查工作区和暂存区，区分用户已有改动与本次改动。

可用的只读检查：
```text
git status --short
git diff
git diff --cached
```

- 不执行 `git stash`、`git commit` 或 `git push`；需要时为用户准备精确命令与摘要。
- 不丢弃用户改动，不静默强推或重写历史；冲突先理解两边意图、确认保全方式，再在授权范围内解决。
- 提交准备只包含与当前交付直接相关的文件（最小改动集）；排除凭据、环境秘密、大二进制与无关运行产物。
- 有需要时建议 `<type>(<scope>): <subject>`，正文解释原因；一次提交聚焦一个可审查问题。
- PR 描述先说具体问题与结果，再列必要验证（区分 `[已实测验证]` 与 `[未验证]`）、兼容影响和回滚方式，不重复会话过程。
- 仅用户明确要求时进入 PR/发布操作；先完成适用验证和审查，用户手动推送后才进行依赖远端分支的步骤。
- 发布前核对版本、配置示例、迁移说明与恢复路径；未验证生产行为不能写成发布成功。
