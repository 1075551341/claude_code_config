# 工程检查参考

仅在对应任务需要时读取。

- 复用已有模块与依赖；局部问题做最小改动，多处重复或共性缺陷优先在公共层统一修正以便扩展迭代，不为“优雅”或假设未来加间接层。
- 不做不必要兜底：禁止添加静默回退（silent fallback）、宽泛默认值或空捕获掩盖异常；缺前置条件、配置错误或异步失败直接暴露原因并向上传播或交由调用方处理。
- 先保证可维护、可测试、可回滚；内部废代码可在本次影响面内清理，公共契约有意变更时提供迁移说明，并在变更后逐一走查消费者且确认旧引用清零。
- 尊重项目清单、锁文件、CI 和现有运行时；缺少必要工具时说明具体缺口，不擅换包管理器或升主版本；新增依赖须有明确收益。
- 外部输入在系统边界验证；命令参数化，认证、授权和资源归属分别核验，不依赖静默兜底放行。
- 时间、随机性和网络等难以复现依赖，在业务逻辑确需时使用可注入接口；遵守项目时区和库选择。
- 性能先测量，关注热点、N+1、批量 I/O 和并发边界；不凭直觉过早优化。
- 保留目标编码/BOM/行尾，修改后检查文件内容；禁止不安全 shell 拼接批量覆盖。
- 新行为与缺陷修复补充正向及边界/预期失败测试；避免只复刻实现或为了绿灯放宽断言。
- 文档、注释、配置示例与实际行为同步更新，历史记录保留当时语义并标注替代关系。
