# 工程检查参考

仅在对应任务需要时读取。

- 复用已有模块与依赖；复杂或安全敏感能力优先成熟方案，但新增依赖须有实际收益。
- 职责清晰、接口尽量小；重复带来真实维护成本再抽象，不为“优雅”增加间接层。
- 先保证可维护、可测试、可回滚；内部废代码可在本次影响面内清理，公共契约变更提供迁移说明。
- 尊重项目清单、锁文件、CI 和现有运行时；缺少必要工具时说明具体缺口，不擅换包管理器或升主版本。
- 外部输入在系统边界验证；命令参数化，认证、授权和资源归属分别核验。
- 异常明确处理或向上传播；异步操作必须检查最终结果，不用空捕获掩盖失败。
- 时间、随机性和网络等难以复现依赖，在业务逻辑确需时使用可注入接口；遵守项目时区和库选择。
- 性能先测量，关注热点、N+1、批量 I/O 和并发边界；不凭直觉过早优化。
- 保留目标编码/BOM/行尾，修改后检查文件内容；不要用不安全的 shell 拼接批量覆盖。
- 新行为与缺陷修复补充能说明问题的测试；避免只复刻实现或为了绿灯放宽断言。
- 文档、注释、配置示例与实际行为一起更新，历史记录保留当时语义并标注替代关系。
