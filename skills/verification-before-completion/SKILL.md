# 验证与审查

## 形成可复查证据

- 对照**用户原始需求原文**与验收标准逐项定位实现、测试或实际输出，不以“未发现错误”代替实测。
- 严格区分 **`[已实测验证]` / `[代码推断]` / `[未验证]`** 三态证据；失败与未运行项明确列出。
- 验证力度与风险相称：低风险小改跑直接相关检查；**缺陷修复、升档、高风险变更及审核验证必须覆盖正向功能 + 反向/预期失败 + 边界条件三类实测**，并回归受影响既有行为及同类调用点。
- 变更名称、路径、签名或配置键后，**逐一走查消费者并确认活跃旧引用清零**（区分历史文档与活跃配置）。
- 配置类改动须核对作用域、合并结果、加载来源与实际行为；**文件存在、安装登记或脚本退出 0 不能单独证明生效**；不为了证明隔离停用或重命名用户正在使用的配置。
- 重读修改文件，确认文档/示例/注释一致且敏感输出已脱敏；安全任务按需读同包 `references/security.md`。

## 独立审查（高风险或显式请求）

- 移交审查包必须提供：**用户原始需求原文**、批准设计（含非目标）、**有意行为变更与保持不变契约对照**、起点与当前完整差异，以及上述三类实测观察输出。
- 由全新、非实现者的只读角色独立核对，不受上轮问题清单限制；工程审查核验质量与回归，安全审查核验安全边界，不重复第二套流程。
- 统一采用**两道关**核验（缺任一或仅凭存在/退出 0 声称生效均不得 `PASS`）：
  1. **符合预期要求**：逐条满足原始需求、无遗漏、无错改、无范围外扩改、问题已解决、无不必要兜底。
  2. **原功能保持**：相对起点无静默回归、公共层共性点与消费者旧引用已清零、有意变更已明确列出且影响范围受控。
- 有必须修项或三类实测证据不全即判 `NEEDS-CHANGES`，证据充分才判 `PASS`。汇总必修项一次修齐重验后，换全新审查者复审；连续 ≤2 轮无进展停下回报阻塞与所需决策。

## 完成报告

简洁报告改了什么、为什么、三态验证结论与未验证项；审查派发、文件落盘或计划获批均不等于完成，缺少必要证据保留待验状态，用户明确豁免须标明实际未验证风险。
