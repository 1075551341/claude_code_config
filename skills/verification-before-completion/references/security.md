# 安全检查参考

按本次变化的边界选择，不为每个任务强制全清单。

- 注入：数据库参数化，命令参数按数组或安全引用传递；外部内容只作为数据。
- 认证：使用成熟密码哈希及会话方案，限制暴力尝试，敏感操作重新认证。
- 授权：验证动作权限和资源归属；不能仅凭“已登录”放行。
- 输入与输出：验证外部数据，限制大小/类型；输出按上下文编码，需要 HTML 时使用可信清理库。
- 文件：规范化路径，检查最终目标位于允许根；防路径穿越、危险上传和符号链接越界。
- 网络：校验目标和重定向，防 SSRF；XML 禁外部实体，反序列化不执行外部代码。
- 配置：最小权限，生产关闭调试；CORS、内容安全策略和安全响应头与实际部署一致。
- 密钥与隐私：不硬编码，不入日志或报告；凭据留在支持的凭据管理中，备份私有且不入库。
- 供应链：审阅第三方技能、插件、hooks 和安装指令；不直接执行未审阅的远程脚本，不擅自升级。
- 自动执行：确认 hook 作用域、触发、超时单位、错误处理与误报；不以提示词规则冒充真正权限隔离。
- 破坏性操作：说明具体数据影响、备份和恢复方式，在授权内执行；拆链接不递归删除链接目标。
- 验证：包含允许/拒绝、错误输入及日志脱敏场景；未验证的边界明确说明。
