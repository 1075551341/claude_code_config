# 任务分类 task-triage

> P0 路由集（L1 常驻）。本 skill 是「简单/非简单」判定的**唯一 SSOT**；CLAUDE.md / gate_messages / using-superpowers 一律引用本文件，禁止各处复制矩阵正文。
> 设计依据：`spec/task-difficulty-precision/design.md`（v10.13）。

## 分类树（两大类 → 使用类型）

```
任务
├── 简单（必须同时满足：Phase0 已盘点 + 关联需改≤2 + 白名单 + 六维全低 + 模型匹配低 + attempt=1）
│   ├── 文档类：拼写/格式/注释/文档补写
│   ├── 实现类：单一纯函数实现（无接口变更）
│   ├── 配置值类：配置值修改（非结构）
│   └── Bug类：可复现 + 根因明确 + 关联需改≤2
└── 非简单（任一条件不满足，或持续处理执行升档）
    ├── Bug类：多文件/根因不明/需复现 → triage(P0-P3) → systematic-debugging
    ├── 功能类：新功能/多文件实现 → grill → brainstorming → 五阶段全链
    ├── 架构类：架构/重构/跨模块设计 → grill → brainstorming
    ├── 配置类：配置结构/hook/rule/skill/agent/MANIFEST/依赖升级/数据迁移 → grill → brainstorming
    ├── 删除类：删除/移动/重命名文件 → grill 确认不可逆性
    └── 调研类：技术选型/深度调研 → deep-research（L3 双源）
```

> **定义（v10.16 客观化）**：
> - **接口变更** = 任何对外签名变化（含可选参数新增/删除、返回类型收窄/拓宽、导出增删）；内部私有函数重命名不算
> - **根因明确** = 附根因证据一行（失败日志/断点/最小复现），无证据则降级非简单

## Phase 0 — 前置盘点（分类前强制）

**未盘点不得宣称「简单」。** 只读探测，**Phase0 不产出文件计数、不允许宣称关联需改≤2**；文件计数以 change-impact 阶段 1 输出清单为准。输出简表后进入六维判定：

1. **已知文件/制品**：相关路径、已有 plan/spec/digest、INDEX/MANIFEST 归属
2. **已知工具**：codegraph 索引是否可用、MCP、hooks/gate 是否已注入
3. **记忆**：claude-mem 相关偏好/历史决策（R18；不可用则标注跳过）
4. **重复问题去重（v10.16 强化）**：强制前置——`claude-mem search` 关键名词（不依赖 issue-tracker hook 注入；hook 为辅助信号）；同会话/跨会话疑似同一问题 → 必须先查 claude-mem + 上轮制品/结论，禁止重新盘点式从头重做；上轮方案失败 → 换方案（R5）+ 执行升档非简单
5. **成功标准草稿**：1 句可验证结果（供分类契约复用）

盘点中发现关联需改将 **>2** 或命中黑名单 → **直接非简单**（跳过「简单候选」）。

## 六维判定矩阵（唯一 SSOT）

| 维度          | 低(1)            | 中(2)                | 高(3)                                              |
| ------------- | ---------------- | -------------------- | -------------------------------------------------- |
| ①关联需改文件 | **≤2**           | —（死档已消：≥3 由判定顺序#1 直接拦截为非简单）       | ≥3                                                 |
| ②变更风险     | 纯文本/格式/注释 | 单模块逻辑/配置值    | 配置结构/hook/rule/skill/agent/依赖升级/DB/API签名 |
| ③跨模块影响   | 无共享符号       | 局部共享             | 改接口/类型/MANIFEST depends_on 目标/多模块调用链  |
| ④需求歧义度   | 成功标准可一行写出且用户已确认 | 部分模糊             | 多义/缺成功标准/需用户决策                         |
| ⑤不可逆性     | 可回退(增改)     | git 可回滚           | 删除/覆盖/强推/数据迁移                            |
| ⑥模型匹配     | 当前档 ≥ 所需档  | 边界（可做但易返工） | 明显不足 → 强制非简单                              |
| ⑥注  | 所需档由②③⑤自动派生（全低→light；含中→mid；含高或黑名单→frontier），禁止臆造  |  |  |

**① 计数口径**：change-impact 阶段 1 输出清单中**需 Edit 的逻辑源文件**；Phase0 只读探测不计、不产出计数；同一逻辑文件的 sync/软链/插件镜像副本只计 1。

### ⑥ 模型档映射（防虚报）

| 档         | 典型模型（据会话实际自报，禁止臆造更高档）          |
| ---------- | --------------------------------------------------- |
| `frontier` | Opus 级 / o3 级 / high-thinking 重推理档            |
| `mid`      | Sonnet 级 / GPT-5 中档 / Composer 主会话默认档      |
| `light`    | Haiku / Flash / mini / 子代理默认廉价档             |

- 所需档：①–⑤ 全低 → light 即可；含中 → 至少 mid；含高或黑名单 → frontier
- `当前档 < 所需档` → ⑥=高 → 非简单（建议换模或走非简单流程）
- `当前档 = 所需档` 且任务在边界 → ⑥=中 → grill 兜底
- `当前档 > 所需档` 且其余全低 → ⑥=低（允许简单）

## 判定顺序（严格收窄）

0. **Phase0 前置盘点**（见上）
1. **关联需改前置**：需 Edit 文件数 **>2** → 直接非简单
2. **黑名单命中 → 非简单**：删除/移动/重命名文件；改 hook/rule/skill/agent/MANIFEST/配置结构；依赖升级/数据迁移；改共享接口/类型签名；跨模块调用链
3. **白名单命中（≤2 前提下）→ 简单候选**：文档类(拼写/格式/注释)；实现类(单一纯函数，无接口变更)；配置值类(非结构)；Bug类(可复现+根因明确)
4. **六维计分**：任一维"高"→非简单；全"低"→简单候选；含"中"→grill 兜底
5. **⑥ 模型匹配不通过 → 非简单**
6. **无法判定 → 默认非简单**（兜底 grill）
7. **分类输出契约**（强制）：见下节
8. **执行中重估**：清单膨胀>2 / 黑名单新现 → **立即执行升档**非简单；持续处理 → **验证全量 + 执行升档**（见下）

**简单 = Phase0 已盘点 + 关联需改≤2 + 白名单 + 六维全低 + 模型匹配低 + attempt=1，缺一不可。**

## 分类输出契约（强制一行）

分类完成后必须输出（可表可句）：

`大类 | 需改文件列表 | 模型档(当前≥所需) | verify_tier | 置信度 | 成功标准(1句)`

- verify_tier 两档定义 SSOT → `skills/verification-before-completion/SKILL.md`「verify_tier」节；本文件只引用取值
- 置信度低 → 按非简单或 grill 处理

## 简单路径 — 一次改完（attempt=1）

1. Read change-impact → 清单必须**完整且 ≤2**；中途膨胀 >2 → **立即执行升档**（禁止拆成多次「还是简单」）
2. 拓扑序**一次改齐**关联文件；配置类同步 INDEX + MANIFEST + 相关 docs
3. `verify_tier=比例`；贴命令证据
4. **禁止**「先改一点再看」式多轮简单旁路

## 持续处理 → 验证全量 + 执行升档（默认同时）

初判可为简单；若之后仍继续处理同一问题，则：

- **verify_tier=全量**
- **执行升档为非简单处理流程**（按使用类型路由；不再停留简单旁路）

**触发（任一）**：

1. 同会话同任务 `attempt ≥ 2`（已改一轮后又继续改同一问题）
2. 用户反馈未解决 /「还是不行」/ 继续修同一 bug
3. 简单路径验证未通过后继续处理（非放弃）
4. 首轮处理后问题仍在，再次动手

**声明**：`初判=简单；已执行升档=非简单；verify_tier=全量（持续处理）`

**升档后路由**：

| 使用类型           | 执行链                                                                 |
| ------------------ | ---------------------------------------------------------------------- |
| Bug/可复现修复     | Read systematic-debugging → 全量验证；成功标准仍歧义才 grill           |
| 功能/架构/配置/删除 | **grill** → brainstorming → … → 全量验证                               |
| 调研               | deep-research → 全量验证（适用时）                                     |

**其他执行升档**（须走非简单链或停空转）：清单膨胀>2；黑名单新现；同方案达 R5（≤2 次）仍失败 → 停空转 / NEEDS_CONTEXT / grill。

## Grill（非简单任务执行前）

非简单（含执行升档后的功能/架构/配置/删除）在 Read 任何实现类 skill 之前，必须先访谈用户（一次一问 + 推荐答案）：

1. 需求目标与验收标准是什么？
2. 范围边界：可改什么、不可改什么？
3. 风险与不可逆点：哪些操作不可回退？
4. 优先级与约束：时间/兼容/性能限制？
5. 期望输出形态？

≤5 问收敛；grill 确认后仍需设计 → Read skills/brainstorming/SKILL.md（HARD-GATE：用户批准设计前禁止实现）。

**例外**：持续处理升档的 Bug 类且用户在本会话已明确给出可验证成功标准（引用用户原话）→ 可跳过 grill，直接 systematic-debugging。

## 路由（按使用类型）

| 大类   | 使用类型                               | 路由                                                                                                      |
| ------ | -------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| 简单   | 文档/实现/配置值/Bug(关联需改≤2可复现) | Phase0 → change-impact → **一次改齐** → verification（比例；仅 attempt=1）                              |
| 非简单 | Bug（多文件/根因不明/执行升档）        | （歧义则 grill）→ triage(P0-P3，L3) → systematic-debugging → 全量验证                                    |
| 非简单 | 功能/架构/配置/删除                    | **grill** → brainstorming → 五阶段全链 → 全量验证 + 修改→审查循环（最多 3 轮） |
| 非简单 | 调研                                   | deep-research（L3 双源）                                                                                |

## 边界

- **默认不执行 TDD/SDD（v10.15）**：仅用户显式要求（TDD/测试驱动/先写测试/子Agent派发）时才 Read `test-driven-development` / `subagent-driven-development`；非简单任务默认由主会话按五阶段骨架直接执行，不强制测试先行、不强制子Agent派发。
- task-triage = 任务复杂度判定 + 需求级访谈（grill）；triage = Bug P0-P3 分级。互补不重叠。
- brainstorming = 设计级访谈（HARD-GATE 批准方案）；grill 只做需求澄清，不重复设计访谈。
- catalog/skills/grill-with-docs = 文档对齐拷问，与需求访谈语义不同。
- 验证细节 SSOT → `skills/verification-before-completion/SKILL.md`；**升档触发**归本文件；非简单完成前须 修改→验证→审查循环（最多 3 轮），见 executing-plans。
- attempt 由会话契约自报；issue-tracker hook（v10.15）辅助识别同问题重复出现并注入提醒，但分类/升档判定仍以会话契约为 SSOT。
