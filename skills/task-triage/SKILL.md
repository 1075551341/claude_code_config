# 任务分类 task-triage

> P0 路由集（L1 常驻）。本 skill 是「简单/非简单」判定的**唯一 SSOT**；CLAUDE.md / gate_messages / using-superpowers 一律引用本文件，禁止各处复制矩阵正文。

## 分类树（两大类 → 使用类型）

```
任务
├── 简单（必须同时满足：关联需改≤2 + 白名单 + 六维全低 + 模型匹配低）
│   ├── 文档类：拼写/格式/注释/文档补写
│   ├── 实现类：单一纯函数实现（无接口变更）
│   ├── 配置值类：配置值修改（非结构）
│   └── Bug类：可复现 + 根因明确 + 关联需改≤2
└── 非简单（任一条件不满足）
    ├── Bug类：多文件/根因不明/需复现 → triage(P0-P3) → systematic-debugging
    ├── 功能类：新功能/多文件实现 → grill → brainstorming → 五阶段全链
    ├── 架构类：架构/重构/跨模块设计 → grill → brainstorming
    ├── 配置类：配置结构/hook/rule/skill/agent/MANIFEST/依赖升级/数据迁移 → grill → brainstorming
    ├── 删除类：删除/移动/重命名文件 → grill 确认不可逆性
    └── 调研类：技术选型/深度调研 → deep-research（L3 双源）
```

## 六维判定矩阵（唯一 SSOT）

| 维度          | 低(1)            | 中(2)                | 高(3)                                              |
| ------------- | ---------------- | -------------------- | -------------------------------------------------- |
| ①关联需改文件 | **≤2**           | 3–5                  | >5                                                 |
| ②变更风险     | 纯文本/格式/注释 | 单模块逻辑/配置值    | 配置结构/hook/rule/skill/agent/依赖升级/DB/API签名 |
| ③跨模块影响   | 无共享符号       | 局部共享             | 改接口/类型/MANIFEST depends_on 目标/多模块调用链  |
| ④需求歧义度   | 明确可复现       | 部分模糊             | 多义/缺成功标准/需用户决策                         |
| ⑤不可逆性     | 可回退(增改)     | git 可回滚           | 删除/覆盖/强推/数据迁移                            |
| ⑥模型匹配     | 当前档 ≥ 所需档  | 边界（可做但易返工） | 明显不足 → 强制非简单                              |

**① 计数口径**：change-impact 清单中**需 Edit 的逻辑源文件**；只读探测不计；同一逻辑文件的 sync/软链/插件镜像副本只计 1。

**⑥ 模型匹配**：

- 首轮分类自报当前模型档：`frontier` / `mid` / `light`（据会话实际模型，禁止臆造更高档）
- 所需档：①–⑤ 全低 → light 即可；含中 → 至少 mid；含高或黑名单 → frontier
- `当前档 < 所需档` → ⑥=高 → 非简单
- `当前档 = 所需档` 且任务在边界 → ⑥=中 → grill 兜底
- `当前档 > 所需档` 且其余全低 → ⑥=低（允许简单）

## 判定顺序（严格收窄）

1. **关联需改前置**：需 Edit 文件数 **>2** → 直接非简单
2. **黑名单命中 → 非简单**：删除/移动/重命名文件；改 hook/rule/skill/agent/MANIFEST/配置结构；依赖升级/数据迁移；改共享接口/类型签名；跨模块调用链
3. **白名单命中（≤2 前提下）→ 简单候选**：文档类(拼写/格式/注释)；实现类(单一纯函数，无接口变更)；配置值类(非结构)；Bug类(可复现+根因明确)
4. **六维计分**：任一维"高"→非简单；全"低"→简单候选；含"中"→grill 兜底
5. **⑥ 模型匹配不通过 → 非简单**
6. **无法判定 → 默认非简单**（兜底 grill）
7. **分类输出契约**（强制）：见下节
8. **执行中重估**：清单膨胀>2 / 黑名单新现 → 执行升档为非简单；持续处理 → 仅升验证档（见下）

**简单 = 关联需改≤2 + 白名单 + 六维全低 + 模型匹配低，缺一不可。**

## 分类输出契约（强制一行）

分类完成后必须输出（可表可句）：

`大类 | 需改文件列表 | 模型档 | verify_tier | 置信度 | 成功标准(1句)`

- `verify_tier`：`比例`（简单且 attempt=1）| `全量`（非简单，或持续处理升档）
- 置信度低 → 按非简单或 grill 处理

## 持续处理 → 验证升档（不自动升执行档）

初判可为简单；若之后仍继续处理同一问题，则 **verify_tier=全量**（非简单交叉验证），执行旁路可仍为简单，除非同时触发执行升档。

**触发（任一）**：

1. 同会话同任务 `attempt ≥ 2`（已改一轮后又继续改同一问题）
2. 用户反馈未解决 /「还是不行」/ 继续修同一 bug
3. 简单路径验证未通过后继续处理（非放弃）
4. 首轮处理后问题仍在，再次动手

**效果**：声明 `初判=简单；verify_tier=全量（持续处理）`；Read verification-before-completion 并跑**交叉验证全项**。

**执行升档**（须走非简单执行链）：验证失败且需扩 scope；需改膨胀>2；黑名单新现；同方案达 R5（≤2 次）仍失败 → 停空转 / NEEDS_CONTEXT / grill。

## Grill（非简单任务执行前必做）

非简单任务在 Read 任何实现类 skill 之前，必须先访谈用户（一次一问 + 推荐答案，沿用 brainstorming relentless interview 纪律）：

1. 需求目标与验收标准是什么？
2. 范围边界：可改什么、不可改什么？
3. 风险与不可逆点：哪些操作不可回退？
4. 优先级与约束：时间/兼容/性能限制？
5. 期望输出形态？

≤5 问收敛；grill 确认后仍需设计 → Read skills/brainstorming/SKILL.md（HARD-GATE：用户批准设计前禁止实现）。

## 路由（按使用类型）

| 大类   | 使用类型                               | 路由                                                                                    |
| ------ | -------------------------------------- | --------------------------------------------------------------------------------------- |
| 简单   | 文档/实现/配置值/Bug(关联需改≤2可复现) | Read change-impact → 执行 → Read verification-before-completion（比例；持续处理则全量） |
| 非简单 | Bug（多文件/根因不明）                 | Read skills/triage（P0-P3，L3）→ Read skills/systematic-debugging → 全量验证            |
| 非简单 | 功能/架构/配置/删除                    | **grill** → Read brainstorming → 五阶段全链 → 全量验证                                  |
| 非简单 | 调研                                   | Read skills/deep-research（L3 双源）                                                    |

## 边界

- task-triage = 任务复杂度判定 + 需求级访谈（grill）；triage = Bug P0-P3 分级。互补不重叠。
- brainstorming = 设计级访谈（HARD-GATE 批准方案）；grill 只做需求澄清，不重复设计访谈。
- catalog/skills/grill-with-docs = 文档对齐拷问，与需求访谈语义不同。
- 验证细节 SSOT → `skills/verification-before-completion/SKILL.md`（本文件只定 verify_tier 与升档触发）。
