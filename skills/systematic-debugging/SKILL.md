# 根因调试

1. **严重度分诊**：
   - **P0（数据丢失/安全事件/生产不可用）**：先止血并立即告知用户，再排查根因。
   - **P1–P3（核心/局部/边缘缺陷）**：按影响排定排查顺序；局部故障不升档为完整设计流程。
2. **建立最小复现与现场核实**：记录环境、输入、预期与实际，读完完整报错并确认失败可观察；外部库/接口行为以项目锁文件源码或官方文档为准，缺源标 `[未验证]`，禁止凭记忆编造。
3. **分层假设验证**：沿入口到失败点每次只验证一个可证伪假设，必要时加最小插桩，不靠改业务逻辑试错。
4. **≤2 次止损换向**：同一假设或修复连续失败 ≤2 次且无新证据时立即停下，重置前提或换路；顽固/间歇/性能疑难故障若本端方法库包含 `catalog/skills/diagnose/SKILL.md` 可按需读取。
5. **公共根因修复与同类清扫**：在真实根因修复（共性缺陷修在公共层并横向检查同类调用点），严禁在调用处加静默回退或空捕获掩盖上游缺陷。
6. **三类回归验证**：运行**正向功能 + 反向/预期失败 + 边界条件**实测，保留修复前失败与修复后通过输出并按验证标准标注证据状态。
