# 根因调试

1. 建立最小复现：记录环境、输入、预期和实际，先确认失败可观察。
2. 收集失败日志、错误栈和相关状态；写下一个能被证伪的根因假设。
3. 沿入口到失败点分层排除，每次只验证一个假设；必要时加最小插桩，不靠改变业务逻辑试错。
4. 根因须解释全部观察证据；证据相反时修正假设，不反复重跑同一无效方案。
5. 以最小相关改动修复；横向检查同类调用点，确认相同缺陷没有遗漏。
6. 使用可重现用例或回归测试证明问题消失，再验证受影响的原有行为；保留失败与成功输出。

数据丢失、安全事件或生产不可用先止血并告知用户；局部问题按影响处理，不把所有故障升级为完整设计流程。

不得吞掉异常、删除失败测试或以“看起来正常”替代结果。报告直接原因、根本原因、证据、修改点和回归结果。
