# 根因调试

1. **严重度分诊**：
   - **P0（数据丢失/安全事件/生产不可用）**：先止血并立即告知用户，再排查根因。
   - **P1–P3（核心/局部/边缘缺陷）**：按影响排定排查顺序；局部故障不升级为完整设计流程。
2. **建立最小复现**：记录环境、输入、预期和实际，先确认失败可观察。
3. **分层假设验证**：收集失败日志、错误栈和相关状态，写下可证伪假设；沿入口到失败点每次只验证一个假设，必要时加最小插桩，不靠改业务逻辑试错。
4. **≤2 次止损换向**：同一假设或修复连续失败 ≤2 次且无新证据时，停止微调并重新检查前提或切换路径；顽固、间歇性或性能疑难故障可按需读 `catalog/skills/diagnose/SKILL.md`。
5. **公共根源修复，严禁兜底掩盖**：以最小相关改动修在真实根因；若属多处共性缺陷，优先修在公共层以便复用迭代，并横向检查同类调用点。**严禁在调用处加空判、静默回退或空 `catch` 掩盖上游缺陷**。
6. **正反向回归**：用原失败用例/回归测试及边界场景证明缺陷消失且原有行为保持，保留失败与修复后输出，标注 `[已实测验证]`。

不得吞掉异常、删除或削弱失败测试换取绿灯。报告直接原因、根本原因、实测证据、修改点与回归结果。
